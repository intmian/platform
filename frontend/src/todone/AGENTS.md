# Todone（含 Library 娱乐库、例行清单）

同一套层级 `目录 → 分组 → 子分组 → 任务`，分组类型决定页面：`0` 普通任务板、`1` Library、`2` 例行清单（`Main.tsx` 按类型分发）。后端都在 `backend/services/todone`，权限 `admin|todone`，请求里的 `UserID` 必须等于登录用户。

## 地址与外壳

- 已定：`/todone` 是关注页，`/todone/g/<groupId>` 是分组页（`route.ts`）。地址里只有分组 ID，所在目录链、标题、类型都从 `getDirTree` 查；目录树加载完才渲染分组页，查不到就显示“清单不存在或已删除”。
- 旧地址 `/todone/<encodeURIComponent("dir-1/dir-5/grp-12|标题|2")>` 还在 iOS 主屏幕图标里，取最后一个 `grp-N` 替换成新地址，不能删。
- 以前“直接打开分组偶尔是空列表”：旧地址带着目录链，分组移到别的目录后，后端按 `(ParentDirID, GroupID)` 找不到就报错，前端不提示，看着像空清单。现在目录链只从目录树取，加载失败会提示。
- Todone 在外壳里保活：切走后 DOM 还在、路由冻结在离开时那一页。不能直接读写 `window.location`/`window.history`（Library 的筛选参数用 `useSearchParams`，在后台时不写）；回到前台刷新的逻辑要同时挂 `useAppActive`；标题用 `useAppTitle`；挂在 body 上的抽屉在后台要关掉（`open && useIsAppActive()`）。
- 请求都走 `net/send_back.ts`（底层是 `common/api.ts`），导出的函数签名不要改，调用方很多。
- 目录里分组的 `⋯` 菜单有“添加到桌面”，桌面链接就是 `/todone/g/<id>`。

## 关注页（`Overview.tsx`，`/todone` 不带分组时显示；菜单里叫“关注”）

拍过板的产品决定：
- 整页只看收藏的清单。上半部分从收藏里挑出**带日期**的事：主栏按逾期、今天、进行中分段（今天截止、今天开始、例行今天到期的进“今天”），旁边是接下来 7 天、按天排的日程（只看不能勾，点了跳到清单）。没设开始/截止日期的任务（常开着的、DOING、插旗）不进上半部分，只在收藏卡片里；没收藏的清单完全不出现。
- 普通任务：开始日期没到的进“接下来”（7 天以外不显示）；过了截止、或标成未开始却过了开始日期的算逾期；其余进行中。**新建任务默认 `Started` 为真**，不能拿它当“有没有开始”的主要依据。
- 例行清单设了周期的节奏层进上半部分（今天到期的进“今天”，宽限期内的算进行中）；手动节奏只在收藏卡片里。只收藏了清单里的一栏时，节奏层只算这一栏里的事项。娱乐库不参与。
- 收藏可以是整个分组，也可以是其中一个子分组（`group_favorites.sub_group_id`，0 表示整个分组），按收藏先后排列。整个分组收藏了，它下面单独收藏的子分组不重复显示；只有一个子分组的分组，收藏入口里不单列子分组。
- 上半部分每行下面的来源文字可以点，跳到清单里的原位置并闪一下（`locate.ts`，靠任务行的 `data-todone-task`、栏的 `data-todone-subgroup` 找；任务所在的栏收起时退到定位那一栏）。收藏卡片行尾的定位按钮只在鼠标移上去时出现，触屏不显示。
- 收藏卡片里不重复列上面（含接下来）已经出现的事，底部写“N 项在上面”；被藏起的任务下面的子任务提到它的位置。
- 宽屏（≥1000px）主栏和日程左右并排；收藏卡片按列往下排（≥700px 两列、≥1100px 三列）。窄屏都是单列，统计数字单独一行。
- 上半部分里带多个事项的例行节奏层：标题行带进度，事项排成小胶囊铺开，点一下勾一项。
- 勾选区域和清单页同一个规矩：只有标题那一条（圆圈 → 标题 → 右侧标签）能勾，节奏层点它勾整层；下面的来源文字只跳转，胶囊各勾一项，胶囊周围和其余空白不响应（曾经整行可点，胶囊外一碰就勾掉整层）。定位按钮只跳转不勾选。
- 这次页面里勾掉的项先留在原处划掉，方便撤销，下次加载才消失。

实现上的坑：
- 一个请求 `getOverview` 拿全部数据：分组和子分组全给，任务只给收藏范围内的（例行清单只要被收藏到一栏就整张返回，否则清单级的节奏算不对）。后端持锁只做目录树快照，D1 查询在锁外并发执行。任务从活着的分组往下查，再丢掉父链断掉的子任务（删分组是软删、删子分组是硬删、父任务完成后子任务在库里仍未完成，都不会处理下面的任务）。
- 返回的任务不带 `Note`，所以总视图勾选走 `setTaskDone`（只改完成状态），绝不能拿这些任务调 `changeTask`，否则会清空备注。
- 例行清单的模型（`routineModel.ts`）由清单页和总视图共用，判断规则只改这一处。
- 上半部分的归类（逾期、今天、进行中、接下来）在 `focusModel.ts`，桌面“今天”卡片（`shellApi.ts` 的 `loadTodayDigest`）也用它，规则只改这一处。

## 搜索（`search.tsx`）

- 普通任务板和例行清单的页头都有搜索，匹配标题和备注、忽略大小写，命中处标黄。只显示命中的项和通往它们的上级（强制展开）；某一层自己命中时，下面的内容照常显示不再过滤。搜索时不显示新增入口，例行清单也不分“暂不用做”。
- 普通任务板只搜已加载的任务（默认不含已完成）。娱乐库有自己的搜索。

## 普通任务板

- 拖动和批量移动都走 `taskMove`；跨子分组移动后要刷新源、目标两个子分组。
- 已知控制台里 antd 的 `Select.Option` 弃用警告、mock R2 的域名解析失败，都不影响功能。

## Library（`Library*.tsx`）

数据边界：
- 一个作品 = 一个 Task，核心结构是 `Task.Note` 里的 `LibraryExtra` JSON。私人备注在 `library_notes` 表，评分详情（评语、模式、多维度）在 `library_score_details` 表。
- 每个周目有稳定的 UUID，备注和评分详情都按 `task_id + round_id`（评分再加 score id）绑定，绝不用数组下标或名字。主评分用 `mainScoreID`。
- 增删改备注、改评分详情都不改写 `Task.Note`，也不刷新作品的 `updatedAt`。`LibraryLogType.note` 只用于历史迁移，运行时不能再写。
- 列表上派生的状态、评分只存在内存里，不加后端字段。
- 评分详情只在用户明确打开、编辑、分享某个评分时按 ID 加载；列表、时间线、评分梯度、隐藏的弹窗都不能触发加载。
- 私人备注永远不进全库时间线、筛选和导出。

规则：
- "鸽了"：最新状态是 WAIT、没写原因、持续 30 天以上。写了原因就不算。
- 默认排序：DOING、WAIT、无状态、TODO、DONE、鸽了、GIVE_UP、ARCHIVED；同状态里收藏优先，再按 `updatedAt` 倒序。
- `updatedAt` 只在手动"刷新"或最新一条非备注、非时间线截止的记录变化时更新。
- 封面上传三份：原图 `pictureAddress`、2:3 详情图 `pictureAddressDetail`、480 宽预览图 `picturePreview`。列表读取顺序是预览图优先，详情和分享读取顺序是详情图优先，缺了就逐级回退；旧数据缺图时由前端后台补生成。
- 打分时的 AI 助手（`library.reviewNotesDigest`）只读当前周目的备注，只输出优点、缺点、值得记录的点，不自动填任何字段。

## 例行清单（`Routine*.tsx`、`routineRule.ts`）

拍过板的产品决定：
- 只有设了规则的那一层（清单、子分组、分组、事项）才有节奏。没设规则的子项只是普通勾选框，跟随最近的上级：上级到了刷新日，它们一起清空重来。子项自己设了节奏就各走各的，不受上级刷新影响，也不计入上级的完成判断。
- 一层的勾选、计数、进度条只管跟它同一节奏的事项；全是各自节奏子项的分组只当容器，不显示勾选框。
- 不提前：到了刷新日才开始，没到就是"X 开始"（未开始，不能勾，不计进度）。
- 刷新当天没做完，第二天起算逾期；可以设"宽限 N 天"。到下一个刷新日还没做完，照样清空，标"前 N 期没做"。
- 刷新方式：手动、每 N 天、每 N 周的周几（可多选）、每 N 个月（月、季度、半年、年，按自然年对齐）的几号、最后一天或第几个周几，以及"完成后 N 天"（顺延）。
- 本次补充（Temp）不会自动删除，到了刷新日只清空勾选。只有"清空重来"会处理它们，弹窗里每项可以选择"留下"转为常驻。"清空重来"只清手动节奏下的勾选。
- 可选项不影响"这一期是否做完"。
- 分组和事项长得一样（没有文件夹图标）。顶层卡片额外有外框、进度条、逾期红点和"清空重来"；其他能力每一层都一样。
- 卡片里只有"+ 事项"和"+ 本次补充"；分组就是加了子项的事项，在事项编辑面板里"添加子项"。
- 清单没设过节奏时默认是手动，这时不显示"手动重置"；跟随来的手动也不显示。"清空重来"只在真有可清的内容时出现。
- 界面上不写纯说明性的提示（比如逾期怎么算），用户自己知道。
- 事项在页面上分三种：要做、今天做完（手动节奏勾了就一直算这类）、暂不用做（之前做完在等下一次，或第一次还没到）。暂不用做的收进每一层底部的"暂不用做 N 项 · 最早 X"。只影响摆放，不影响勾选和进度。
- 只在打开页面、或跨天后回到前台时整理一次（`Arrangement` 快照），当场勾选不挪位置、分组勾完也不当场收起。整理时没有要做也没有今天做完的分组默认收起，手动展开只在这次整理内有效；顶层卡片不因此收起（里面已经收进“暂不用做”，再收一层多点一次），只有停用的卡片收起。
- 停用（`routine_nodes.paused`）：卡片（子分组）和事项都能停用，留着不删；停用的叶子不能勾，不算进度、逾期，也不进关注页，子项跟着停。停用的事项当场收进“暂不用做”那一行（不另开一行），停用的卡片留在原位、收起变淡。恢复时不翻旧账：跟随上级的回到上级这一期待做；自己有节奏的，这一期还在期限内就待做，过了期限就跳过这一期等下次刷新（`resumeNodes`）。
- 每次回到前台都重新拉数据（有未保存的写入时跳过）。"隐藏已完成"只管今天做完的。

实现上的坑：
- 后端只存不透明的 `rule`/`mark`（`routine_nodes` 表），所有日期都由前端按本地日期算。叶子的勾选是"勾选日期 ≥ 本期开始"才算数，刷新不写库。
- 取消一个已完成的节奏层时，要用 `PrevMark` 或 `undoneMark` 恢复，不能清空成空串，否则会被当成"从没做过"而显示逾期很多天。
- 拖动：每行外面包着带裁剪的折叠容器，拖动时其他行不能平移（否则会被裁掉），被拖的行用 `DragOverlay` 浮层；落点要用指针的真实坐标，dnd-kit 的位移不含页面滚动。
- 勾选区域：每一行只有标题那一条（圆圈到右侧按钮之前）能勾，分组也一样勾整组；标题行下面（备注两侧、行底空白）不响应，备注文字点了是展开。两个页面、所有行都按这一条，不按单项/多项区别对待。
- 行上的把手、展开箭头、`⋯` 都是整行高度的直角点击区，避免点偏误勾。
- 顶层卡片排序：拖动后把所有子分组的 `Index` 重排成 1..n，用 `changeSubGroup` 保存；后端只在 `Index > 0` 时才改，0 表示没带。老数据里可能有重复的 Index。
